# 方向与架构边界

本轮为候选目标规划，不是获批详细设计。

- 建议主线：让用户知道为什么没译/何时能看，让服务配置可以自查，让复杂文档与译文质量可量化改进。
- 默认继续复用原生Hover、现有TranslationCoordinator、安全AST和SecretStorage。
- 不预先引入Webview框架、多引擎统一抽象、持久化文档库或全局自动重试。
- 自动原地刷新、对单个AST块保留特殊链接、配置连接测试涉及不同风险与数据发送语义；实施前分别明确设计与验收。
- 对自动翻译文档的现有同意不推定为任意选区/源码上传授权。
- 用户已选定优化方向；具体版本范围、实现方案和最终GateB尚未批准，不进入代码。

## 范围建议与替代选项

- 推荐范围：G1等待反馈/光标处查看+G2配置诊断+G3质量样本和针对性改进；先补状态和证据，复用现有通路。
- 较小替代：只做G1/G2，质量仅补基线。交付更轻，但译文质量诉求改善较少。
- 较大替代：同时加入G4安全分块/G5自动刷新。技术风险与结果不确定性更高，不建议捆绑首个版本。
- 候选文件图、验证、回滚与后置目标详见docs/next-stage-roadmap.md；这不是已通过独立架构设计的GateB包。

## 详细设计决策包（续篇）

用户已明确授权 G1/G2/G3 详细设计；G4/G5 独立验证。旧段落为上一轮记录，以下为当前推荐。

三路只读架构镜头：design_waiting（最小复用/生命周期）、design_diagnostics（权限/服务保护）、design_quality_spikes（质量证据/兼容边界）。主代理核验关键文件后整合：

- G1：两个现有 provider 增加小型 activity tracker 和 acquire 订阅观察。最近完成只陈述完成事实，放弃 CacheRef/缓存元数据查询扩展；不保证永久命中。手动命令只触发原生光标处查看，同目标在途不打断，不在网络完成后重开窗口。
- G2：本地诊断零 HTTP；固定样本单次同意独立于项目文档同意；同协调器 diagnostic purpose，不读写文档缓存。取消/失效与配置阻断解除拆开，所有刷新保留冷却/频率记录，避免多服务状态表。
- G3：30 例覆盖/结构/语义分别评估；先建议6例真实样本基线、必要时6例候选提示比较（每批需明确预算后再执行），采用比子方案12+12更小的首批范围。统一提示/codec版本，不凭空改prompt。
- G4：只验证安全顶层块与特殊源块隔离；跨块/同段特殊内容保守回退。G5：先证明可见性/归属与关闭竞态，无法证明即no-go。
- 替代：仅改文案不足；新阅读器/统一文档服务/缓存查询平台与自动刷新扩大范围，暂不采用。

完整数据流、状态、接口、文件图、测试、迁移回滚及限制：docs/next-stage-detailed-design.md。独立验证范围与停止条件：docs/next-stage-validation-plan.md。

风险分类为高风险（未来实现涉及并发、权限、凭据和网络）。当前交付为Gate B可审阅包；没有执行Phase5或Phase6，不把设计复核当代码审查。产品仍0.4.0，未来目标0.5.0。
