# 悬停翻译展示优化设计

版本：设计稿 v1 · 2026-10-31  
状态：用户已批准实施，目标版本0.2.0；执行记录见 `.planning/hover-display-v2/` 与 `verification.md`。设计基线：1e8fe2b / 插件 0.1.0。

## 1. 目标与结论

用户已真实安装插件并使用 deepseek-flash 看到译文；本次明确优先改善“中文排版与信息层级”。推荐采用 **原生 Hover 内的紧凑中文阅读 + 可选逐段对照**。

目标是让读者在译文区迅速找到说明正文、参数、返回值和注意事项，同时保持内容完整。沿用公开 Hover API、原文采集协调器和异步追加路线；不改云端协议、不新增模型摘要、不改变文档外发范围。设计交付后，用户明确批准实施并升级安装包。

预览是布局示意，不是实际 VS Code 截图。字号、行距、颜色、窗口尺寸、滚动和多个提供者的最终位置由 VS Code 决定；本设计不承诺中文固定置顶，也不能隐藏其他扩展提供的英文。

## 2. 当前问题与证据

| 问题 | 本地证据 | 阅读影响 |
| --- | --- | --- |
| 中文区固定三级标题，内部源标题原样输出 | `src/hover/hoverDocumentProvider.ts:42`；`markdownCodec.ts:111–120` | 短说明标题占比大；源 H1/H2 可能抢过译文区标题 |
| 复制完整 AST，只替换可译文字 | `markdownCodec.ts:111–120` | 中文区再次出现语言服务签名；示例也重复，但示例通常有阅读价值 |
| 对照统一采用“原文 + 硬换行 + 中文” | `markdownCodec.ts:115` | 缺少明确分组，标题臃肿；表格序列化后实际挤成同一行 |
| 部分翻译仅在总标题注明 | `hoverDocumentProvider.ts:42` | 很难识别哪段受字符预算限制 |
| 显示切换也重建缓存、重置请求池 | `src/extension.ts:17–21,31` | 纯排版操作可能导致再次请求与等待 |

以上是代码与只读样例分析所得；尚未观察用户当前窗口的具体截图。已有真实 DOM 测试只检查英文先显示、中文后到和缓存命中，没有验证视觉层级。

## 3. 方案比较

| 方向 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 只缩小中文标题 | 改动很小 | 重复签名、对照和表格问题仍在 | 不足以满足本次目标 |
| 原生 Hover + 本地呈现规则 | 编辑习惯不变，保留主题与键盘体验 | 可控的是内容结构，不能任意设置 CSS | **推荐** |
| 独立中文阅读侧栏 | 可设计完整布局，适合长篇阅读 | 需要新的入口、结果绑定与面板生命周期 | 作为后续独立功能 |

## 4. 默认模式：中文阅读

### 4.1 内容层级

1. 原生英文 Hover 由语言服务照常提供。
2. 插件区用单行粗体 **中文说明**，替换固定 `### 中文翻译`。
3. 紧接说明的首段译文；它是原段落翻译，不是额外生成的摘要。
4. 有现成章节时保留其顺序和嵌套关系；没有章节时不强加“功能/参数/返回值”模板。
5. 保留列表、内联代码、强调、安全链接、示例代码和说明中的限制条件。
6. 仅发生预算不足时，在标题下一行显示“部分内容未翻译，已在对应位置标注”。正常结果不附带模型名、耗时、缓存状态等元数据。

示意（参数和返回值须源文档本来存在）：

```text
中文说明

读取配置文件并返回解析结果。

参数
• path — 配置文件路径。
• encoding — 文本编码，默认为 UTF-8。

返回值
解析后的配置字典。
```

### 4.2 排版规则

| 元素 | 规则 |
| --- | --- |
| 区块标题 | 普通段落中的粗体“中文说明”，不额外插入多层分隔线 |
| 说明段落 | 按原段落翻译；不逐句拆开、不合并不同段落 |
| 源章节标题 | 每份源文档最浅标题映射到 H4，更深层级映射到 H5/H6；原有深层次保留在 AST，不生成额外章节 |
| 参数与返回值 | 保留源列表或段落结构；代码标识符不翻译，不自动转成宽表格 |
| 强调与提示 | 原有加粗/引用继续保留；不依赖额外红绿颜色表达含义 |
| 示例 | 原代码内容、语言标识、顺序不变；不隐藏示例来缩短高度 |
| 表格 | 中文阅读模式保留单份源表格结构，替换可译单元格；宽表格仍可能需要原生横向滚动 |
| 链接 | 安全 HTTP(S) 链接保持可点击；不添加模型生成 URL 或命令链接 |

H4–H6 的具体视觉大小须在真实 VS Code 确认；若目标主题不能形成清晰层级，优先保留语义标题并调整映射，不启用 HTML/CSS。

### 4.3 保守减少重复签名

保留 `Hover → contents` 边界，仅在**同一 Hover 中独立的签名内容项**满足已验证样本规则，并且同一 Hover 还有正文说明时，才从插件的显示投影中省略。该项须仅由签名组成，例如完整匹配规则的 `(function) ...` 或独立 fenced 签名；仅“位于第一项”或“代码围栏语言是 typescript”均不足以判定。

未知、多行复杂重载、混合说明与签名、正文中的代码块全部保留。只做本地显示省略，不从原生 Hover 删除，不根据模型判断签名，也不改变进入翻译链路的 segments。无法可靠识别的样本宁可重复。

不做跨提供者模糊句子去重：两个参数可能合法使用同一句说明。

## 5. 可选模式：中英对照

默认仍为中文阅读。对照适合核对术语，允许更长；不作为缩短悬停的方案。

| 节点 | 对照规则 |
| --- | --- |
| 段落 | 中文在前；其后以原生引用块显示“原文：…” |
| 列表项 | 保持同一条列表项，译文段落后添加原文引用，不改变编号或嵌套 |
| 标题 | 单套标题，格式为“中文标题 · English heading”；相同文本仅保留一次 |
| 表格 | 完整中文表格，其后标注“原文表格”并展示完整原表格；不用单元格硬换行或 HTML `<br>` |
| 代码示例 | 在插件区保留一次，不因对照模式复制两份 |
| 已有中文/不可译节点 | 保留一次，不制造伪对照 |
| 预算未覆盖节点 | 原文保留一次并标注；不能冒充译文 |

原文引用使用 VS Code 的主题样式，不指定灰色低对比文本。原本已处于引用块中的段落也保留语义父结构；必要时允许嵌套引用，需通过嵌套样本确认可读性。

## 6. 长文档、部分结果与等待

- 不添加新的默认截断，不自动摘要，不隐藏异常、弃用和警告。现有字符预算保持。
- 给未覆盖段落或标题加本地标签“原文保留（超出本次翻译预算）”；连续同级未译段落可共用一次标签，但不能跨列表项、标题或表格分组。
- 表格含未覆盖单元格时，在表格前显示“此表部分内容超出翻译预算，未译内容保留原文”。不得向模型索要原因或为每个单元格拼大段标签。
- 必须区分 `translated`、`budgetSkipped`、`preserved`；代码、标识符和已有中文不能标成预算不足。
- 等待时保留现有英文与状态栏活动提示；翻译完成后返回最终中文块。继续使用单次异步结果，不设计 Hover 内会自行更新的进度条或流式打字效果。
- 请求失败继续保留原文，通过既有状态栏/诊断反馈。本轮不新增每次悬停弹窗。

## 7. 显示方式菜单

将“切换中英对照”改为明确的选择入口：**显示方式 · 中文阅读** / **显示方式 · 中英对照**。

- 中文阅读（默认）：插件区以中文呈现，语言服务原文仍保留。
- 中英对照：插件区按段落先中文后原文，适合核对术语。

显示当前选择，选当前项不写配置；选择其他项后告知“下一次悬停生效”。保留既有 `toggleDisplay` 命令 ID 和 `translationOnly` / `paired` 配置值，只更新标题与解释；旧用户设置无需迁移。

展示偏好必须独立于接口配置是否完整来读取。无须增加悬停内按钮、快捷键或独立侧栏。

## 8. 实现设计（待实施）

### 8.1 数据路径

```text
原始 Hover（保留来源/内容项边界）
  → 原有 Markdown 清理、保护、segments 提取
  → 原有缓存/翻译/校验
  → 本地显示投影（节点翻译状态、保守签名省略、标题层级）
  → hoverMarkdownRenderer（中文阅读/对照/预算说明）
  → 不可信、禁用 HTML 的 MarkdownString
```

显示投影只在本次文档处理上下文中保存，不将 AST、URI 或显示模式放入内容缓存。相同源文档与预算在两种模式下必须产生相同 segments、顺序、ID、保护标记和缓存键；不改变 prompt2-codec2 语义。若后续实际改动改变提取协议，必须单独评估并升级缓存版本。

### 8.2 模块职责

- `markdownCodec.ts` 继续独占源清理、保护、还原与模型文字转义。提供恢复后的安全 AST 与节点状态；renderer 不自行拼接未经清理的模型 Markdown。
- 新增 `src/content/hoverMarkdownRenderer.ts`，负责已还原安全 AST 的标题层级、对照分组、预算注记、粗体区块标题与序列化。
- 源内容元数据可增加 `sourceId/contentIndex`，只在内存使用；对每个原内容项的 reference definitions 仍分别解析，不能破坏原有链接作用域。
- 先对同一安全源树生成译文树及状态，再做显示投影；签名省略不可改变翻译选择/预算。
- renderer 只输出标准 Markdown；`isTrusted=false`、`supportHtml=false` 保持。

### 8.3 展示偏好与配置失效

保留不可变 Settings 快照，不为排版引入新的并发模型。

1. 收到配置事件后，用当前 revision 读取新有效配置。
2. 比较全部非展示字段；只有 `paired` 变化才属于纯展示变更。
3. 纯展示变更替换 config 对象，保持 revision，不 reset 请求池/缓存，也不清除 401 阻断或 429 冷却。
4. 已开始的 Hover 按开始时捕获的模式完成；下一次 Hover 使用新模式并复用仍有效的缓存。
5. 同时改变 endpoint/model/预算/启用状态等时，仍走原有完整失效流程。密钥、同意和信任变化也保持原流程。
6. 打开菜单可能使 VS Code 自己取消 Hover。承诺是“显示配置变化不主动取消任务”，不是保证当前窗口绝不关闭。

配置分类测试必须覆盖同一事件同时改变显示方式和 endpoint；不能只检查 `affectsConfiguration(displayMode)` 就提前返回。

## 9. 验收与实施顺序

先完成纯呈现规则和对应样本，再接保守签名识别，最后改显示选择器与配置分类；每步保持可回退。实施时内容展示为中等复杂度；配置失效改动涉及任务生命周期，需按高风险部分补充安全/并发评估，不能仅因它属于显示设置而降低审查。

| 验收项 | 通过标准 |
| --- | --- |
| 中文阅读 | 标题紧凑，源章节和列表次序保持，参数/返回/异常/警告不遗漏 |
| 安全与内容 | 内联代码、示例、链接目标逐字保持；模型注入的 HTML/Markdown 仍是普通文本 |
| 签名 | 已确认独立签名只在原生区出现；未知签名和正文示例保留 |
| 对照 | 段落中文在前，有原文标签；标题单套，列表编号不变，表格为两份完整结构 |
| 部分结果 | 未译位置能识别，已有中文和代码不误标；无全篇已译的误导提示 |
| 缓存 | 同一内容切模式后的云请求总数仍为 1（在有效缓存内）；进行中模式快照稳定 |
| 配置安全 | 同时修改显示/endpoint 仍失效；关闭、撤回同意、换密钥仍取消旧任务；切模式不解除 401/429 |
| 视觉 | Windows 本地 VS Code：浅色、深色、高对比；约 360/520/720px 窄宽 Hover；不引入额外正文横向滚动 |
| 可达性 | 键盘进入 Hover 和模式选择菜单可用；不靠颜色区分中英与未译 |

样本覆盖 Python Google/NumPy docstring、Args/Returns/Raises、JS @param/@returns/@throws/@deprecated、复杂签名、代码示例、引用、嵌套列表、GFM 表格与长链接。未知结构保真回退。预览中的模拟内容不替代这些真实语言服务样本。

运行现有 typecheck/unit/integration；补相关回归后在隔离 VS Code 检查 DOM 和截图。设计阶段不需要重新跑未修改的生产测试。真实供应商可选人工复核排版，不需要为展示测试发起付费请求。

回退时恢复 renderer/配置分流相关代码即可；无密钥、同意或数据迁移。旧 VSIX 保持可安装。先前独立审查并不覆盖这次尚未实施的设计。

## 10. 调研来源与限制

- [VS Code HoverProvider](https://code.visualstudio.com/api/references/vscode-api#HoverProvider)：多 Hover 合并，提供者返回单个结果或 Promise。
- [VS Code MarkdownString](https://code.visualstudio.com/api/references/vscode-api#MarkdownString)：Markdown、受限 HTML、命令信任；据此限定原生排版能力。
- [VS Code command URI](https://code.visualstudio.com/api/extension-guides/command#command-uris)：悬停命令链接需要信任，本轮不引入。
- 本地实现、单元测试、集成测试及两轮独立只读探索/架构建议。Context7 未检索到准确官方库，采用官方网页与本地实现交叉核验。
